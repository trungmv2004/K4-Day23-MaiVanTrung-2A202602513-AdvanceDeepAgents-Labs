# A Comprehensive Survey on Large Language Model Agents and Tool Use: Paradigms, Collaboration Architectures, and Security Challenges

## TL;DR
- Large Language Model (LLM) agents synergize verbal reasoning and external tool execution through interleaved reasoning-action paradigms like ReAct [1], self-supervised API learning like Toolformer [2], and retriever-augmented fine-tuning like Gorilla [3].
- Multi-agent orchestration architectures leverage horizontal peer-to-peer teams, vertical hierarchies, and shared message pools via prominent frameworks such as AutoGen, MetaGPT, CrewAI, and LangGraph [4][5][6].
- Security evaluations reveal severe vulnerabilities in agentic tool-use pipelines, including Indirect Prompt Injections (IPI) and ToolHijacker attacks with success rates exceeding 80-99% [7][8][9], necessitating structural defenses such as provenance projection and capability allowlists [10].

## Background
The evolution of Large Language Models (LLMs) from static text predictors to autonomous, action-enabled agents represents a fundamental paradigm shift in artificial intelligence. Historically, autoregressive models were constrained by static training corpora, rendering them prone to hallucinations when answering real-time factual queries, executing complex calculations, or interacting with software environments. To overcome these limitations, researchers introduced tool-use and agentic learning capabilities, enabling LLMs to perceive external environments, invoke APIs, execute code, and query databases [11][12]. Foundational work established that prompting strategies and self-supervised fine-tuning can teach models when and how to call specialized tools [1][2]. For instance, ReAct demonstrated that interleaving verbal reasoning traces (`thoughts`) with environment `actions` allows models to dynamically plan, track, and recover from execution errors [1]. Similarly, Toolformer proved that language models can autonomously learn to insert API calls by filtering synthetic training traces based on perplexity reduction [2]. In parallel, Gorilla addressed massive, overlapping API ecosystems by introducing Retriever-Aware Training (RAT), which conditions the LLM on retrieved API documentation JSON to minimize argument hallucination [3]. These foundational breakthroughs transformed LLMs from isolated conversational engines into active agents capable of orchestrating complex software workflows.

## Foundational Paradigms and Architectural Foundations
The architectural foundation of LLM agent tool use centers on augmenting the model's action and language spaces. In the ReAct framework, the model operates over an augmented action space $\hat{\mathcal{A}} = \mathcal{A} \cup \mathcal{L}$, where $\mathcal{L}$ represents internal verbal thoughts that guide multi-turn execution without directly altering the external environment [1]. While ReAct relies on linear sequential reasoning, advanced tool learning paradigms incorporate tree-based decision planning (such as ToolLLM's Depth-First Search Decision Tree, DFSDT) and programmatic code generation where models synthesize entire execution workflows into executable code snippets [11]. 

To scale beyond a handful of pre-trained tools, Toolformer introduced a self-supervised acquisition pipeline where candidate API calls are sampled and retained if they reduce cross-entropy loss in predicting subsequent tokens [2]. However, static fine-tuning becomes impractical when facing tens of thousands of rapidly evolving enterprise APIs. Gorilla solved this challenge through Retriever-Aware Training (RAT), which dynamically injects retrieved API documentation into the model's context during training and inference, enabling the LLM to accurately populate arguments and adapt to API schema modifications [3]. Comprehensive surveys categorize these foundational approaches into input-space augmentation, output-space correction, and iterative self-play mechanisms that govern how models interface with external software utilities [11].

## Multi-Agent Collaboration and Execution Frameworks
As tasks grow beyond the capacity of isolated agents, research has increasingly focused on multi-agent collaboration frameworks and advanced execution topologies [12][13]. Multi-agent systems (MAS) are characterized by actor configurations, cooperative-competitive dynamics, structural topologies, and communication protocols [13]. Structural topologies divide systems into horizontal (equal peer participation) and vertical (hierarchical leader-worker reporting) architectures, alongside shared message pools and decentralized networks [4][6].

Prominent software frameworks operationalize these architectures through distinct abstractions. AutoGen provides flexible conversable agents that communicate via natural language and code execution [4][6]. MetaGPT encodes Standardized Operating Procedures (SOPs) into structured multi-agent prompt sequences and shared message pools, ensuring role alignment and reproducible software development workflows [4][6]. CrewAI emphasizes role prompting and process-driven sequential task execution [5][6], while LangGraph facilitates graph-based state management and cyclical workflow orchestration [5][6]. Furthermore, architectural innovations like Mixture-of-Agents (MoA) leverage layered hierarchies where multiple proposer models generate candidate outputs that are iteratively refined by aggregator models [5], and emerging communication protocols such as Model Context Protocol (MCP) and Agent Network Protocol (ANP) standardize secure interoperability between agents and external tools [6].

## Evaluation Benchmarks, Security, and Robustness
Rigorous evaluation of LLM agents requires moving beyond static natural language benchmarks to dynamic, multi-environment interactive testbeds. AgentBench established a systematic evaluation framework across eight environments spanning code (operating systems, databases), games, and web navigation, revealing a pronounced performance gap between proprietary commercial models and open-source models under 70B parameters [14].

However, high task completion rates do not equate to security robustness. Agent Security Bench (ASB) and AgentSecBench formalize adversarial threat models across agent lifecycles, evaluating Direct Prompt Injections (DPI), Indirect Prompt Injections (IPI), memory poisoning, Plan-of-Thought backdoors, and tool-selection poisoning [7][8][10]. Tool-use agents are particularly vulnerable due to an architectural flaw: models process trusted system instructions, retrieved RAG context, and untrusted tool observations through a shared generative channel, thereby conflating data flow with authority [10]. ToolHijacker demonstrates that injecting a single optimized malicious tool document into a library can hijack tool selection with success rates exceeding 80% to 99% across benchmarks like ToolBench [8]. Furthermore, AgentInjectionBench reveals that naive keyword filters catch fewer than 27% of agentic injections because malicious payloads hide inside tool outputs, multi-turn states, and MCP tool definitions [9]. Mitigating these vulnerabilities requires structural defenses—such as provenance projection, least-privilege capability allowlists, and pre-generation channel closure—rather than superficial prompt-level warnings [9][10].

## Trends and open problems
Over the past two years (2024–2026), research in LLM agents and tool use has shifted from heuristic single-turn prompting to sophisticated graph-based multi-agent orchestration, standardized protocol integration (such as MCP), and rigorous security benchmarking [11][5][6][9][10], alongside broader investigations into agentic skills [15]. Despite these advancements, several critical open problems and limitations persist:
- **Data-Authority Conflation:** Current agent architectures fail to isolate trusted control channels from untrusted data feeds, leaving systems susceptible to advanced indirect prompt injections and cascading tool-selection hijackings [8][9][10].
- **Compounding Error Cascades:** In long-horizon multi-turn deployments, small execution errors or ambiguous tool error messages compound exponentially across agent steps, leading to catastrophic task drift.
- **Latency-Security Trade-Offs:** Rigorous pre-generation provenance checks, capability allowlisting, and multi-agent debate protocols introduce substantial computational overhead and operational latency [5][9].
- **Standardization and Interoperability:** While protocols like MCP provide promising abstractions, unifying disparate tool ecosystems, enterprise permission boundaries, and decentralized agent communication remains an unsolved frontier [6][9].
